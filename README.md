# DiplomNavigator

**Система выбора тем и сопровождения выпускных квалификационных работ.**

DiplomNavigator помогает студентам выбирать темы ВКР, научным руководителям —
рассматривать заявки и отслеживать выполнение работ, а заведующим кафедрой —
контролировать закрепления и нагрузку преподавателей.

Основной процесс: **тема → заявка студента → решение руководителя → закрепление →
выполнение работы → допуск к защите**.

## Возможности

| Участник | Возможности системы |
|---|---|
| Студент | Просмотр доступных тем, подача заявки, просмотр своей работы и её статуса |
| Научный руководитель | Рассмотрение заявок, просмотр своих студентов, обновление этапов и прогресса работ |
| Заведующий кафедрой | Управление темами и закреплениями своей кафедры, контроль нагрузки руководителей |
| Администратор | Управление учётными записями и назначение ролей |

Система учитывает лимит студентов у руководителя и не допускает нескольких активных
закреплений за одним студентом. Доступ к операциям проверяется на сервере.

**Текущий статус:** серверная часть MVP работает с PostgreSQL и доступна для
демонстрации через Swagger. Интерфейс React/Vite — отдельный прототип с локальными
данными; интеграция с сервером пока не выполнена.

## Локальный запуск

Самый короткий способ запустить сервер и базу данных — Docker Compose.
Потребуются **Git** и запущенный **Docker Desktop** в режиме Linux containers.
Команды ниже предназначены для PowerShell и выполняются из корня проекта.

### 1. Подготовить проект

```powershell
git clone --branch develop https://github.com/Darknesslog/DiplomNavigator.git
cd DiplomNavigator
Copy-Item .env.example .env
```

Если проект уже скачан, используйте существующий каталог. Копируйте шаблон настроек
только при отсутствии своего `.env`.

Откройте `.env` в редакторе и задайте:

| Параметр | Значение для локальной демонстрации |
|---|---|
| `SECRET_KEY` | Собственный случайный секрет длиной не менее 32 байт |
| `POSTGRES_PASSWORD` | Собственный пароль базы данных; для простого запуска — буквы и цифры |
| `SEED_PASSWORD` | Собственный пароль тестовых пользователей длиной 12–128 символов |
| `APPLICATION_DECISION_TIMEOUT_MINUTES` | `20160` — 14 дней на рассмотрение новых заявок |

В `DATABASE_URL` укажите тот же пароль, что и в `POSTGRES_PASSWORD`.
Остальные значения можно оставить из шаблона. Если порт PostgreSQL `5432` занят,
измените `POSTGRES_PORT` и порт в `DATABASE_URL`, например на `5433`.
Внутреннее подключение приложения к БД Docker Compose настраивает автоматически.

### 2. Запустить сервер и загрузить демонстрационные данные

```powershell
docker compose up -d --build
docker compose exec app alembic upgrade head
docker compose exec app python -m backend.scripts.seed
docker compose exec app python -m backend.scripts.create_admin
```

Последняя команда предложит ввести данные первого администратора.
Загрузка демонстрационных данных создаёт темы, студентов и научных руководителей;
повторный запуск не создаёт дубликаты и не меняет пароли существующих аккаунтов.

### 3. Открыть демонстрацию

- [Swagger — интерактивная документация и проверка API](http://127.0.0.1:8000/docs).
- [Проверка доступности сервера](http://127.0.0.1:8000/health) — ожидается `status: ok`.

Адреса приведены для `APP_PORT=8000`. Для входа в Swagger нажмите **Authorize**
и введите email и пароль. Тестовые логины: `seed.student.1@example.com` и
`seed.supervisor.pi@example.com`; пароль — значение `SEED_PASSWORD` при первой
загрузке данных. Администратор использует пароль, введённый при его создании.

Сценарии проверки: **студент подаёт заявку → научный руководитель принимает решение →
руководитель обновляет прогресс и оформляет допуск к защите**.
Пошаговая демонстрация и настройка роли заведующего описаны в [USER.md](USER.md)
и [TRY1.md](TRY1.md).

Остановка сервера и БД с сохранением данных:

```powershell
docker compose stop
```

### Отдельный запуск интерфейса

Для просмотра прототипа установите Node.js и npm; проверенная среда — Node.js 24.
В отдельном терминале из корня проекта выполните:

```powershell
cd frontend
npm ci
npm run dev -- --host 127.0.0.1 --port 5173 --strictPort
```

Откройте [интерфейс](http://127.0.0.1:5173/) и оставьте терминал работающим.
Прототип демонстрирует экраны; для проверки сохранения данных и прав доступа
используйте Swagger.
