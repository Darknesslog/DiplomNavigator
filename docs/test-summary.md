## Отдельные диагностические пробы

[Исходник](review/test_contract_probes.py) запускается явно и не добавлен
в штатную testpaths-выборку. Успех подтверждает наблюдение, а не правильность
продуктового правила. После исправлений нужны тесты на принятый целевой контракт.

| Сценарий | Количество | Наблюдение |
|---|---:|---|
| Перевод студента с pending / active | 2 | 200, старые связи сохраняются |
| Перевод научрука перед одобрением | 1 | 200 и последующее одобрение при разных кафедрах |
| Прямая модерация занятой темы | 2 | archived/rejected дают 200 при active Assignment |
| Подача после окна в draft / archived / open | 3 | 201 во всех состояниях |
| Защита без допуска | 1 | 200, completed |
| Пересечение срока после очистки | 1 | Одобрение при decided_at > expires_at |

Последняя проба управляет временем сервиса после реальной очистки. Она не
использует два потока и не доказывает воспроизведение PostgreSQL-гонки.

Из корня репозитория, после uv sync:

```powershell
uv run ruff check
uv run pytest --tb=short
uv run pytest -c pyproject.toml -p backend.tests.conftest docs/review/test_contract_probes.py -v --tb=short
```

Если Windows-launcher uv выдаёт canonicalize script path, использовать
`& ./.venv/Scripts/python.exe -m pytest` с теми же аргументами.

## PostgreSQL и неповторённые проверки

Предыдущий протокол для 95ca12e содержит 97 passed на изолированной PostgreSQL 16.
В текущем ревью этот запуск не повторялся: доступ к Docker API из песочницы
дал permission denied. Новый CI-run и отсутствие всех конкурентных ошибок
по этим данным не заявляются.

Существующие тесты покрывают миграции, конкурентные назначения/лимиты, RBAC,
rollback и прогресс. Нет проверенного сценария пересечения expires_at во время
ожидания блокировки. Новая приёмка Q1–Q12 описана в [обзоре](backend-review-appts.md).

Не выполнялись: инвентаризация рабочей БД, миграция льготных сроков, ручной
live Swagger, frontend build/regression, нагрузочные испытания и backup/restore.
Google-реестры и обсуждение PR заново не сверялись. Сверка ORM-генераторов
не заменяет применение Alembic к живой PostgreSQL.

При наличии Docker повтор PostgreSQL-набора:

```powershell
./backend/tests/integration/run_postgresql.ps1
```

Раннер создаёт изолированный Compose-проект; подробности:
[integration/README](../backend/tests/integration/README.md).
