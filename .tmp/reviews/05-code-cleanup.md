# Этап 3 — очистка и декомпозиция

Дата: 2026-11-11. Базовая версия для сравнения: c119b34.
[PR #10](https://github.com/Darknesslog/DiplomNavigator/pull/10), без слияния.

## Изменения

- HTTP-обработчики аккаунтов и входа делегируют операции сервисам
  [account_management](../../backend/app/services/account_management.py) и
  [authentication](../../backend/app/services/authentication.py). Проверки ролей,
  блокировки, сохранение неудачных попыток входа и заголовки ответа сохранены.
- [Прогресс и отзыв допуска](../../backend/app/services/progress.py) отделены от
  [решений по заявкам](../../backend/app/services/supervisor.py).
  [Создание закрепления с начальной историей](../../backend/app/services/assignment_records.py)
  используется и одобрением, и ручным назначением; commit остаётся у команды.
- [Заявки на удаление темы](../../backend/app/services/topic_deletion.py) выделены
  из сервиса тем. Строки типов уведомлений заменены существующей системой Enum;
  столбец БД остаётся строковым, миграция не требуется.
- Общие проверки доступности закрепления, периода, резервирования и публикации
  вынесены в именованные функции. Повторная формула срока заявки заменена вызовом
  существующего application_deadline. Порядок проверок, сообщения и порядок
  блокировок Student → Applications сохранены.
- [read_models](../../backend/app/services/read_models.py) получает проверку
  профиля из [profiles](../../backend/app/services/profiles.py), без зависимости
  от сервиса команд. Чтение справочников выделено в
  [directories](../../backend/app/services/directories.py), фильтрация тем — в
  [topic](../../backend/app/services/topic.py). Сортировка ответов сохранена.
- [App](../../frontend/src/App.tsx) стал оболочкой навигации. Экраны вынесены в
  [pages](../../frontend/src/pages/), повторяемые элементы — в
  [components](../../frontend/src/components/), демонстрационные данные — в
  [demo](../../frontend/src/demo/). Состояние каталога и формы хранится через
  [useTopics](../../frontend/src/features/topics/useTopics.ts) на уровне App,
  поэтому переключение страниц не сбрасывает его.
- [CI](../../.github/workflows/backend-checks.yml) дополнен frontend lint/build.

## Repowise: сравнение одной базовой версии с рабочим деревом

Команда: `repowise health --score <file> ... --against HEAD --format table`
до фиксации, когда HEAD = c119b34. Чем выше оценка, тем лучше.

| Файл | До | После |
|---|---:|---:|
| frontend/src/App.tsx | 7.50 | 9.23 |
| services/supervisor.py | 6.03 | 9.00 |
| services/topic.py | 6.26 | 8.33 |
| services/application.py | 7.62 | 9.00 |
| services/workflow.py | 8.77 | 9.85 |

Это оценка выбранных файлов, а не всего проекта. Перенос функций меняет область
анализа; улучшение чисел само по себе не доказывает корректность новых модулей.
Repowise пометил frontend и пустой Rust-файл как возможные кандидаты удаления
с невысокой уверенностью. Они сохранены: frontend — рабочий прототип,
назначение пользовательского пустого файла неизвестно. application_deadline
теперь действительно переиспользуется вместо удаления полезной функции.

## Замечание Greptile о ссылках

Из `.tmp/reviews/` путь `../../backend/` уже ведёт в корневой backend.
Предложенный `../../../backend/` вышел бы выше репозитория. Вместо такого
изменения [генератор](../../backend/scripts/export_method_inventory.py)
вычисляет относительный путь от фактического каталога вывода и поддерживает
пробелы в путях. [Два теста](../../backend/tests/test_method_inventory.py)
разрешают все ссылки в существующие исходники и проверяют номера строк для
обычного и более глубокого расположения отчёта. Каталог пересоздан.

## Проверки и границы

- 125 SQLite-тестов и 97 PostgreSQL-тестов прошли после декомпозиции.
  В PostgreSQL проверены конкурентные решения, блокировки лимитов, rollback,
  аудит, миграционный цикл и ограничения БД. Тестовый контейнер удалён раннером.
- Ruff, диагностика редактора, frontend ESLint и TypeScript/Vite build прошли.
- Начальный экран прототипа проверен в браузере; полный интерактивный
  регрессионный прогон интерфейса не выполнялся.
- Локально pytest запускался через настроенный Python: существующая проблема
  Windows uv trampoline сохраняется. CI использует штатный `uv run pytest`.
- Правила B01/B02/B03/B06 и HTTP-контракты сохранены. Новые операции B04/B05,
  подключение прототипа к API и worker не добавлялись.
- Проекции read_models выполняют только чтение. Явные вызовы истечения резервов
  на уровне API сохранены: некоторые GET-маршруты всё ещё инициируют эту команду.
  Полное исключение записи из GET требует отдельного механизма запуска очистки.
- Демонстрационные строки и данные frontend явно выделены, но не превращены
  в вымышленную конфигурацию или несуществующую интеграцию.

Проверка экспертом: оценить границы сервисов и экранов, сохранение контрактов
и приемлемость оставшихся явных команд истечения резервов в API.
