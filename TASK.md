# Дашборд и Заявки: аудит контрактов

## Источники и область задачи

Задача: сверить Swagger с расшифровкой макетов, дополнить Pydantic-схемы
и подготовить ручки/заглушки для экранов Дашборда и Заявок.
Текст из сообщения заказчика (роли, user flow, endpoints, AC-1–AC-12)
использован как источник требований к макетам. Последующие комментарии
о реализованных ветках учтены отдельно. Визуальная геометрия экранов не проверялась.

Проверенные исходные версии:

- авторизация: `d4ddfb4`;
- `origin/feature/topic-workflow-and-seed-data`: `fbf1ec6`;
- `origin/feature/student-applications-and-timeout`: `01c965c`;
- результат: `feature/dashboard-and-application-contracts`, основана на ветке заявок.

Repowise CLI: `status`, пакетный `context` для API аккаунтов, схем и workflow.
Его индекс относился к `d4ddfb4`, поэтому новые ветки дополнительно сверены
по исходникам. В обоих полученных версиях отсутствовали заявленные read-only
ручки научрука и хранилище истории прогресса.

## Роли, сущности и статусы

| Расшифровка | Код | Область доступа |
| --- | --- | --- |
| STUDENT | `student` | Свои заявки, опубликованные темы своей кафедры |
| SUPERVISOR | `nauchruk`, профиль `Teacher` | Свои темы и закрепления |
| HEAD | `zavkaf`, профиль `Teacher` | Своя кафедра |
| Администратор | `admin` | Глобально; кафедра дашборда выбирается явно |
| Бронирование | `Application` | Намерение студента, отдельной Booking-таблицы нет |
| Работа | `Assignment` | Закрепление после одобрения |

Сохранён процесс `Topic → Application → Assignment`. `user_id`, `student_id`
и `supervisor_id` относятся к разным таблицам.
Машинные статусы остаются в нижнем регистре; `status_label` — подпись для UI.

## Матрица API

Все новые endpoints требуют JWT. «Совместимый путь» использует тот же сервис.

| Требование / экран | Фактический endpoint | Результат аудита |
| --- | --- | --- |
| Вход, профиль | `POST /login`, `GET /me`; алиасы `/auth/login`, `/auth/me` | Префикс добавлен |
| Выход | `POST /auth/logout` | Отсутствует; вне задачи |
| Темы | `GET /topics`, `POST /topics`, `GET /topics/{id}` | Существуют; добавлен `status_label` |
| Редактирование темы | `PATCH /topics/{id}` | Отсутствует; вне задачи |
| Модерация | `PATCH /topics/{id}/status` | Существует; отдельных `/approve` и `/publish` нет |
| Подача заявки | `POST /topics/{id}/applications`; алиас `/topics/{id}/bookings` | Алиас добавлен |
| Свои заявки | `GET /applications/me`; алиас `/bookings/me` | Добавлены |
| Заявки научрука | `GET /supervisor/applications` | Расширены ответ и пагинация |
| Заявки по роли | `GET /booking-requests` | Добавлен; научрук: свои темы, завкаф: кафедра, admin: все |
| Решение | `PATCH /supervisor/applications/{id}/approve` и `/reject` | Прежние сервисы сохранены |
| Решение из макетов | `POST /booking-requests/{id}/approve` и `/reject` | Добавлены алиасы; только `nauchruk` |
| Дашборд научрука | `GET /supervisor/dashboard`; алиас `/dashboard/supervisor` | Добавлены |
| Закрепления | `GET /supervisor/assignments`, `GET /supervisor/assignments/{id}` | Добавлены |
| Студенты научрука | `GET /supervisor/students`, `GET /supervisor/students/{id}` | Добавлены |
| Прогресс | `PATCH /supervisor/assignments/{id}/progress` | Существует; расширен ответ |
| Дашборд кафедры | `GET /dashboard/head` | Добавлен |
| Нагрузка | `GET /workload/supervisors` | Добавлен |
| Изменение лимита | `PATCH /supervisors/{id}/limit` | Отсутствует; вне задачи |
| Работы и файлы | `/works`, `/works/{id}`, `/works/{id}/status`, `/works/{id}/files` | Отсутствуют; вне задачи |
| Отчёты | `POST /reports` | Отсутствует; вне задачи |

Пагинация новых списков и заявок научрука: `offset >= 0`, `limit = 1..100`,
по умолчанию `50`. Ответ — JSON-массив. Заявки фильтруются по `?status=pending`,
закрепления по `?status=active`. Дашборд содержит максимум пять последних
заявок и закреплений, но считает все подходящие записи.

## Источники полей

| Поле | Источник / смысл |
| --- | --- |
| `group_name` | `Student.group.name` |
| `justification` | Копия `Application.motivation`; альтернативный ключ входа |
| `status_label` | Русская подпись enum, не новый статус БД |
| `current_stage_label` | Русская подпись `AssignmentStage` |
| `student` | Публичная карточка без паролей, токенов и счётчиков входа |
| `topic` | ID, название, кафедра, руководитель |
| `expires_at` | Дедлайн решения; старые записи могут содержать `null` |
| `cooldown_until` | Запрет повторной заявки для пары студент–тема |
| `progress_percent` | Текущий процент 0..100 |
| `progress_history` | `null`: история прогресса ещё не сохраняется |
| `current_load` | Число активных закреплений руководителя |
| `available_places` | `max(0, max_students - current_load)` |

Одновременная передача `motivation` и `justification` отклоняется (`422`).
Пустые списки возвращаются как `[]`, нулевые счётчики как `0`, отсутствующие
опциональные значения как `null`.

## Расхождения AC и более поздних комментариев

| Критерий | Реальная версия / оставшееся различие |
| --- | --- |
| AC-1 | JWT получается из login, профиль — отдельным GET `/auth/me` |
| AC-2 | Неверные данные: общий `401` |
| AC-3 | Согласовано ранее: 3 ошибки → `429`, `Retry-After`, обычно 15 минут; не 5 ошибок / `423` |
| AC-4 | Чужая роль: `403`; недействительный JWT: `401` |
| AC-5–AC-8 | Темы: `draft/published/rejected/archived`; отдельного `APPROVED` нет |
| AC-9 | Норма нагрузки и `WORKLOAD_NORM_MISSING` не реализованы |
| AC-10–AC-11 | Исходная ветка использует `Application.pending`; конфликт pending-заявки: `409` |
| AC-12 | Одобрение использует прежнюю проверку нагрузки под блокировкой строки научрука |

Таймаут: `APPLICATION_DECISION_TIMEOUT_MINUTES=2` для demo, `20160` для 14 дней.
Просрочка обрабатывается при обращениях к API, а не фоновым таймером:
заявка → `expired`, тема → `archived`, причина → `expired`.
Отклонение оставляет тему доступной другим студентам; cooldown относится
к конкретной паре студент–тема. Правила исходной ветки этой задачей не заменены.

## Проверки доступа

- Свои заявки студент получает независимо от передаваемых фильтров.
- Чужая/отсутствующая карточка студента или закрепления для научрука: `404`.
  Существующие операции решения сохраняют свой `403` при нарушении ownership.
- В карточке студента только закрепления данного научрука. Для доступа нужен
  `active` или `completed`; отменённое закрепление доступа не предоставляет.
- Завкаф запрашивает чужую кафедру: `403`. Admin не указал `department_id`
  для дашборда кафедры/нагрузки: `422`.
- История статусов заявки и история прогресса работы не смешиваются.
